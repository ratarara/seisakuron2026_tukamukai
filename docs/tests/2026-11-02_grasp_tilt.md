# つかむときの手の傾きと高さ（pick_move）

- 日付：2026-11-02
- 確かめたもの：`pick_place_node` の `mode:=pick_move`。つかむときに指が取っ手を正しく挟むか
- 関係する Issue：#28（置く動作と精度）

## 条件

| 項目 | 値 |
|---|---|
| ロボット | CRANE-X7 実機（USB 変換器のシリアル番号：FT3HLLRD） |
| ピース | L（取っ手の中心を前後 250 mm、左右 0 に置く） |
| 手の位置の目標 | x = 0.25 m、y = 0.0 m、`pick_z` = 0.105 m、手の向き -90° |
| 指 | 開く 10°、つかむ -2° |

## 結果（直す前、実機）

| 項目 | 値 | 出どころ |
|---|---|---|
| 様子 | 指先が奥へ傾き、取っ手ではなく本体を掴んでいるように見えた。持ち上げると落ちた | 目視 |
| 下ろしたときの手のずれ（補正後） | dx +0.6、dy -0.3、dz -10.3 mm | ログ |
| 手の高さの計算値 | 0.105 - 0.0103 = 0.0947 m | ログから計算 |
| 指先の高さの計算値 | 0.0947 - 0.0896 = 約 5 mm（本体の上面が 5 mm） | 計算（傾きは考えていない） |
| つかんだあとの指の角度 | 指令 -2.0°、実際 1.2°（爪の間の幅 約 3.3 mm） | ログ |

## わかったこと

- 補正は手首の付け根の位置だけを合わせていて、手の傾きは直していなかった。手首の付け根から指先まで約 90 mm あるので、傾きが 6°（以前の測定で 6.5°）なら指先は約 9 mm ずれる。取っ手の厚さは 4 mm なので、この量は無視できない
- 指先の高さが本体の上面と同じくらいで、余裕がなかった
- 爪の間の幅が約 3.3 mm なのは、取っ手の厚さ（4 mm）に近い。本体は前後に 40 mm あり、10° の開き（約 27 mm）では挟めない。**本体を掴んだという目視と合わないので、次の測定で確かめる**
- この回の傾きは測っていない（ログに残していなかった）。傾きが原因かどうかは、次の測定で確かめる

## 直したこと

| 内容 | 変更 |
|---|---|
| 手の傾きも測って直す | `correct_position` が向きのずれも補正する（`comp_use_tilt`、初期値 true）。上限 12°（`comp_max_tilt_deg`） |
| つかむ高さを上げる | `pick_z` を 0.105 → 0.108 m |
| つかむ力を上げる | `pick_grasp_deg` を -2 → -4°。指の実際の角度が 1.2° なら、指令との差が 3.2° → 5.2°（力は約 1.6 倍）。グリッパの到着判定の許容差 0.1 rad（5.7°）以内 |
| 上げるときに補正を戻さない | つかんだあと（`lift`）と離したあと（`move away`）も、測ったずらし量を保って上げる |
| ログに出す | `[comp]` の行に、傾き（`tilt front`、`left`）と指先の位置の目安（`fingertip about`） |

## Mock での確認

実機のたわみは Mock では出ないので、`comp_fake_tilt_deg:=6.5` で傾いたものとして測らせた。

| 確かめたこと | 結果 |
|---|---|
| 真上で傾きを補正した後の傾き | 0.0° |
| 最後の動作まで | 全部 OK |
| テスト | 82 件、失敗 0、スキップ 15 |

`mode:=fill_4x4`（`use_d435:=true`、`comp_fake_tilt_deg:=6.5`、つかむ -4°）は 4 個とも動作計画が通り、I を置いて L をつかむところまで確かめた。途中で止めたので、最後までは確かめていない。テストの件数は -4° に変える前の結果。

**実機ではまだ確かめていない。**
