# ソフトウェアの設計（担当ごとの作るもの）

ソフトを「何を作るか」「何のソフトで作るか」の単位で分けたものです。担当はこれを見て作業を始め、細かい手順は各 Issue を見てください。

## 決まっていること

- 言語は **C++17**、すべて ROS 2 のノードにして `tukamukai` パッケージに入れる
- カメラ（RealSense D435）は **ハンドに付ける**。rt-net 公式の [D435 マウンタ](https://github.com/rt-net/crane_x7_Hardware/blob/master/3d_print_parts/v1.0/CRANE-X7_HandA_RealSenseD435マウンタ.stl) を使う
- 座標の単位は **メートルとラジアン**、基準はロボットの土台（`base_link`）

## 全体の流れ

プログラムを4つのノードに分け、1人1つずつ担当します。

```
③ 司令塔（D）
   │ 1.「撮影姿勢へ」          ──▶ ④ 動作（C）──▶ アームが机の上で止まる
   │ 2.「今撮って」            ──▶ ①② 認識（B）──▶ ピースの一覧とケースの位置
   │ 3. ソルバーで解く（D の中）
   │ 4.「これをつかんでここへ」 ──▶ ④ 動作（C）──▶ 1個運ぶ
   └─ 1 に戻る（全部置き終わるまで）
```

1個置くたびに撮り直すことで、置き損ねやずれにも気づけます。

| ノード | 何をするか | 担当 |
|---|---|---|
| ① ピース認識 | 机の上のピースの「種類・位置・向き」を出す | B |
| ② ケース認識 | ArUco マーカーからケースの位置と向きを出す | B |
| ③ 司令塔 | パズルを解き、どのピースをどこへ運ぶかを1個ずつ指示する | D |
| ④ 動作 | 撮影姿勢への移動と、つかんで置く動作をする | C |

## いちばん近いお手本

crane_x7_examples の **`color_detection` + `pick_and_place_tf`** が、このシステムを小さくしたものです。全員まずこれを読んでください（実機と D435 マウンタが必要）。

```bash
ros2 launch crane_x7_examples demo.launch.py port_name:=/dev/ttyUSB0 use_d435:=true
# 別ターミナルで
ros2 launch crane_x7_examples camera_example.launch.py example:='color_detection'
```

| お手本の中身 | 私たちのシステムでは | 担当 |
|---|---|---|
| `color_detection.cpp`：ハンドのカメラで青い物体を HSV で切り出し、深度から位置を求めて tf（`target_0`）として出す | 7色・形の判定と回転角を加え、ピースの一覧を返す | B |
| `pick_and_place_tf.cpp`：tf `target_0` の位置にある物体をつかんで置く | 指示された位置・向きでつかみ、ケースの指定の位置・向きに置く | C |
| （なし） | 撮影姿勢・ソルバー・順番の管理 | D |

コードは `~/ros2_ws/src/crane_x7_ros/crane_x7_examples/src/` にあります。

## カメラがハンドにあることの影響

- **座標変換は自動**：`demo.launch.py` に `use_d435:=true` を付けると、カメラがロボットのモデルに追加される。アームがどんな姿勢でも「カメラがロボットから見てどこにあるか」が tf2 で分かるので、カメラで見つけた位置は tf2 でロボット座標に変換するだけでよい
- **撮影姿勢が必要**：撮るたびにアームを机の上の決まった姿勢に動かし、止まってから撮る。動いている最中の画像はぶれて使えない
- **認識は頼まれたときに1回だけ**：画像を流しっぱなしにして処理するのではなく、司令塔から「今撮って」と頼まれたら1枚処理して結果を返す
- **近すぎると深度が取れない**：D435 は近いと深度が出ない（目安 20〜30cm 以上。データシートで確認）。撮影姿勢の高さはこれより離す
- **シミュレーションでは画像が出ない**：Gazebo でも `use_d435` でカメラの形と位置は出るが、画像を作る設定は入っていない。認識は実機のカメラか、撮った写真で試す

## 担当ごとの指示

### B：認識（① ピース認識、② ケース認識）

| 項目 | 内容 |
|---|---|
| 作るもの | 「今撮って」と頼まれたら、画像からピースの一覧とケースの位置を返すノード |
| 使うソフト | **realsense2_camera**（画像と深度を ROS に流す）、**OpenCV**（HSV で色の切り出し、輪郭、ArUco）、**tf2**（カメラ座標→ロボット座標）、**rqt_image_view / RViz**（結果の確認） |
| 入力 | カラー画像、深度画像（カラーに位置を合わせたもの） |
| 出力 | ピースごとに「種類（I/O/T/S/Z/J/L）、位置 x・y・z、回転角」、ケースの位置と向き。すべてロボット座標 |
| ロボットなしで試す | カメラを机の上に手で構えて試す。カメラもないときは、撮った写真で OpenCV の部分だけ先に作る |
| 完成の目安 | 机にばらまいたピースが全部、正しい種類・位置・向きで出る |
| 参考 | crane_x7_examples の `color_detection`（HSV での切り出し、深度からの位置、tf での出力）、`aruco_detection`（マーカーの位置と向きを tf で出す） |

### C：動作（④）

| 項目 | 内容 |
|---|---|
| 作るもの | 「撮影姿勢へ」「ここのピースをつかんで、ここに置け」の指示を受けてアームを動かすノード |
| 使うソフト | **MoveIt**（C++ の MoveGroupInterface。アームとハンドの経路計算と実行）、**Gazebo + RViz**（シミュレーションで確認） |
| 入力 | 撮影姿勢への移動の指示、または「つかむ位置と向き」「置く位置と向き」 |
| 出力 | 成功したか失敗したか |
| 動作の流れ | 真上へ移動 → 手首を回して向きを合わせる → 下ろす → ハンドを閉じる → 持ち上げる → 置く場所の真上へ → 向きを合わせる → 数mm上まで下ろす → ハンドを開く → 上に逃げる |
| ロボットなしで試す | Gazebo で、位置を決め打ちして試す（認識やソルバーができていなくてよい） |
| 完成の目安 | 決め打ちした位置の箱を、決め打ちした位置と向きに置ける（Gazebo → 実機の順） |
| 参考 | crane_x7_examples の `pick_and_place_tf`（カメラで見つけた物体をつかむ）、`pick_and_place`（決め打ちの位置。Gazebo で動く）、`gripper_control`、`cartesian_path`（まっすぐ下ろす動き） |

注意：カメラとマウンタがハンドに付くので、下ろしたときにカメラが机やケースに当たらないか確かめる。

### D：司令塔（③）とデータの形式

| 項目 | 内容 |
|---|---|
| 作るもの | 上の「全体の流れ」を順に実行するノード。ソルバーで解き、置く順番を決め、1個ずつ動作ノードに指示する |
| 使うソフト | **ソルバー**（完成済みのライブラリ `tukamukai_solver`）、**tf2**（ケースの「何行何列目」をロボット座標に変換） |
| 入力 | ① のピースの一覧、② のケースの位置 |
| 出力 | ④ への指示（撮影姿勢へ／つかむ位置と置く位置） |
| ロボットなしで試す | ピースの一覧を手で作って渡し、出てきた指示を画面に表示して確かめる |
| 完成の目安 | 手で作った一覧から、正しい順番の指示が出る |
| 最初にやること | ノード間のデータの形式（下の案）を決め、B・C と合意する（#29） |

### A：ハード

ソフトの指示は特にありません。次を早めにソフトの担当へ渡してください。

- C へ：取っ手の寸法、マス目の寸法、ピースの高さ
- B へ：ピースの色、ArUco マーカーの大きさと貼る位置
- D435 マウンタの印刷と取り付け

## データの形式（案、#29 で決める）

ノード間のやりとりは、独自のメッセージ型を別パッケージ（例：`tukamukai_msgs`）に定義して使います。

| やりとり | ROS の方式 | 中身（案） |
|---|---|---|
| ③→①② 「今撮って」 | サービス | 要求：なし ／ 応答：ピースの一覧（種類・位置・回転角）、ケースの位置と向き、成功したか |
| ③→④ 「撮影姿勢へ」 | アクション | 目標：なし（撮影姿勢は C が決めて設定ファイルに置く） ／ 結果：成功したか |
| ③→④ 「つかんで置け」 | アクション | 目標：つかむ位置と回転角、置く位置と回転角 ／ 結果：成功したか、失敗した段階 |

- **トピック**：流しっぱなしにするデータ（今回はほぼ使わない）
- **サービス**：頼んですぐ答えが返るもの（認識）
- **アクション**：時間がかかり、途中経過や中断があるもの（アームの動作）

## 進め方

1. **最初の1週**：D がデータの形式を決め、全員で合意する。A は D435 マウンタを印刷して取り付ける
2. **それぞれ偽物のデータで進める**：C は決め打ちの位置で動かし、B は写真や手で構えたカメラで試し、D は手で作った一覧で試す。他の人の完成を待たない
3. **中間発表の前につなぐ**：①②→③→④ をつなぎ、まず1ピース、次に **4×4 をピース4つ（I・S・L・L：水色・緑・オレンジ）で埋める**（#33）。中間までは認識は3色・3種類、ハードはピース4個と 4×4 のケースだけでよい
4. **最終発表に向けて**：全ピースを通しで動かし、何度も試して調整する
