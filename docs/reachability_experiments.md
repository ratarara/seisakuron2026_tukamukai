# ケース配置と届く範囲の実験記録（Mock）

CRANE-X7 が 8×8 ケースのどこまで届くかを、Mock（実機なし）で調べた記録です。
ケースの置き方と 1 マスの大きさを決める根拠として使います。

> **注意**：この記録は、1 マスを 20 mm に決める前（30 mm・25 mm で検討していたとき）のものです。
> 1 マスは 2026-10-05 に **20 mm** に決まり（#31、`hardware/dimensions.md`）、
> `pick_place_node` の初期値も `cell_size` = 0.02、`origin_y` = -0.07 に変えました。
> 20 mm なら 8×8 のケースは 160 mm 角で、下の配置 A・B より小さく収まります。

- 記録日: 2026-10-03
- ブランチ: `feature/pick-place-node`
- 使ったコード: `src/pick_place_node.cpp`、`launch/pick_place.launch.py`

## 実験の条件

| 項目 | 値 |
|---|---|
| 実行環境 | Mock components（実機なし） |
| 関節の可動制限（`set_constraints`） | あり（2 関節を 0°±30°） |
| 上空の高さ | 0.3 m |
| 降下の高さ（`place_z`） | 0.13 m |
| 速度の倍率 | 1.0 |
| ケースの向き | 行が増える向き = ロボットの +X（前）、列が増える向き = ロボットの +Y（左） |
| ケースの設定 | `origin_x` / `origin_y` = マス(行0, 列0)の中心のロボット座標、`cell_size` = 1 マスの一辺 |

座標はロボットの土台（`base_link`）が原点で、単位は m です。

## 実験の方法

`mode:=corners` は、ケースの 4 隅と中央（行・列とも 0 / 7 / 3.5）の 5 か所について、
「上空 → 降下 → 上空」の動作を計画・実行できるかを調べます。
`mode:=rotations` は、1 つのマスの上空で、ソルバーの回転角を 0 / 90 / 180 / 270° と変えて、
手の向きを確認します。

```bash
# 4 隅と中央の確認
ros2 launch tukamukai pick_place.launch.py mode:=corners origin_x:=0.14 2>&1 | grep "\[corner\]"

# 回転の確認（中央のマス）
ros2 launch tukamukai pick_place.launch.py mode:=rotations row:=3.5 col:=3.5 2>&1 | grep "\[rotation\]"
```

## 結果 1: ケースの位置と 1 マスの大きさ（手の向き = -90°）

| 設定 | `cell_size` | `origin_x` | 行方向の範囲（マスの中心の x） | 結果 |
|---|---|---|---|---|
| 初期配置 | 0.03 | 0.19 | 0.19〜0.40 | 奥の行の 2 隅（x=0.40）が届かない。他の 3 か所は OK |
| 配置 A | 0.03 | 0.14 | 0.14〜0.35 | 5 か所すべて OK |
| 配置 B | 0.025 | 0.19 | 0.19〜0.365 | 5 か所すべて OK |

- 左右方向は、どの設定も `origin_y` = -0.105（マスの中心が y = -0.105〜+0.105）。
- ロボットの土台からの水平距離で見ると、届いた最も遠い点は約 0.38 m（配置 B の奥の隅）、
  届かなかった最も近い点は約 0.41 m（初期配置の奥の隅）だった。
  この条件（手の向き -90°、可動制限あり、上記の高さ）では、
  限界は 0.38〜0.41 m の間にあるとみられる。

## 結果 2: 手の向きごとの届き方（配置 A）

`yaw_at_rot0` を変えて、`mode:=corners` を実行した結果。

| 手の向き（yaw） | 手前の 2 隅 | 奥の 2 隅 | 中央 |
|---|---|---|---|
| -90° | OK | OK | OK |
| 180° | OK | OK | OK |
| 90° | OK | OK | OK |
| 0° | OK | OK | **FAILED** |

手の向き 0° だけ、中央（x=0.245, y=0）で失敗した。4 隅（y=±0.105）では成功している。

## 結果 3: 回転テスト（中央のマス、初期配置）

中央のマス（行 3.5、列 3.5、x=0.295, y=0）の上空で、ソルバーの回転角を変えた結果。

| ソルバーの回転 | 手の向き（yaw） | 結果 |
|---|---|---|
| 0° | -90° | OK |
| 90° | 180° | OK |
| 180° | 90° | OK |
| 270° | 0° | **FAILED** |

- `yaw_sign` = -1.0 のとき、ソルバーの回転角が増えると、手は上から見て時計回りに回ることを
  RViz で確認した。ソルバーの「時計回り」と向きが一致している。
- 結果 2 と合わせると、手の向き 0° は、y が 0 に近い位置で失敗する。
  x を変えても（0.245、0.295）失敗したので、奥行きの限界ではなく、
  向きに固有の問題とみられる。

## 現時点の暫定案

- ケースの配置: `cell_size` = 0.03、`origin_x` = 0.14、`origin_y` = -0.105（配置 A）
  - ケースの外枠は、x が 0.125〜0.365、y が ±0.12 の範囲。
- 手の向きと回転角の対応:

| ソルバーの回転 | 手の向き | 状態 |
|---|---|---|
| 0° | -90° | 使える |
| 90° | 180° | 使える |
| 180° | 90° | 使える |
| 270° | 0° | 中央で失敗 |

- 取っ手が 180° 回しても掴み方が変わらない形であれば、
  270° のピースは、掴む向きを 180° 変えて（手の向き 180°）扱える可能性がある。
  これは未確認で、取っ手の形に依存する。
